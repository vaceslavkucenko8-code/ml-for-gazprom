# Развёртывание в Amvera

1. Создайте приложение в https://cloud.amvera.ru/projects .
2. Загрузите код из этого репозитория, ветка main. Для приватного GitHub предоставьте Amvera доступ к репозиторию либо используйте Git-адрес проекта Amvera.
3. Используйте Dockerfile и amvera.yml из корня. Порт приложения — 8765. Одна реплика: очередь заданий рассчитана на один процесс.
4. Постоянное хранилище монтируется в `/data`. Не меняйте `RUNS_DIR` на другую папку: здесь сохраняются результаты и задания.
5. Для первого запуска DATABASE_URL можно не задавать: приложение использует файлы. Это позволяет проверить стенд без отдельной базы, но не закрывает требование PostgreSQL.
6. Для PostgreSQL создайте отдельный ресурс базы в Amvera и добавьте секрет DATABASE_URL вида postgresql://USER:PASSWORD@INTERNAL_HOST:5432/DATABASE. Возьмите значения из настроек своей базы; спецсимволы логина/пароля закодируйте для URL. Не добавляйте секрет в GitHub.
7. Запустите сборку. После статуса готовности откройте адрес, выданный Amvera. Проверьте /health, /docs и главную страницу.
8. Выполните один быстрый поиск. Проверьте открытие карточки и сохранность истории после перезапуска приложения. До этого внешний стенд не считается проверенным.

Docker Compose в Amvera не используется: приложение и база создаются отдельными ресурсами.

Для первоначального запуска без локального перевода ориентируйтесь на 1 ГБ RAM, затем сверяйте реальное потребление в мониторинге; это оценка, не результат нагрузочного теста. Модель перевода не включена в публичную копию. Не покупайте более дорогой тариф только ради перевода до измерений.

В публичном пакете нет сохранённых подборок команды: при первом старте история пустая. Не загружайте исходный датасет или материалы задания во внешний сервис без разрешения на их публикацию. Все созданные через публичный интерфейс результаты доступны посетителям стенда; вводите только публичные технологические темы.

Документация платформы: https://docs.amvera.ru/applications/configuration/docker.html
